# Технические рецепты

> **Инструменты.** Всё, что ниже показано командами оболочки, продублировано
> Python-скриптами в `scripts/` — они не требуют ImageMagick, poppler и curl
> и работают в песочнице исполнения кода: `python3 scripts/archimg.py --help`,
> `python3 scripts/archnet.py --help`. Источник закрыт по географии — поднимите SOCKS
> одной командой `ssh -D 11080 -N you@узел-в-стране` (на самом узле ставить **ничего**
> не нужно, хватает штатного sshd) и добавьте `--socks 127.0.0.1:11080`. Соответствие приёмов и команд — `scripts/README.md`.

Проверенные приёмы доступа, скачивания и просмотра. Все команды — POSIX shell + ImageMagick +
poppler-utils + python3.

## 1. Мёртвый домен и исчезнувшие файлы — Wayback CDX

Ссылка из каталога ведёт на сайт, которого больше нет в DNS. Это **не тупик**:

```bash
curl "http://web.archive.org/cdx/search/cdx?url=<домен>&matchType=domain\
&output=text&fl=original,timestamp,statuscode&collapse=urlkey\
&filter=statuscode:200&limit=2000"

curl -L "https://web.archive.org/web/<timestamp>id_/<url>" -o file.pdf
pdftotext -layout file.pdf file.txt
```
- `matchType=domain` показывает **всё**, что архив когда-либо взял с домена — включая файлы,
  ссылок на которые уже нигде нет;
- суффикс `id_` в URL отдаёт **оригинальный файл** без обёртки Wayback;
- ⚠️ CDX иногда отдаёт 504 — просто повторить;
- ⚠️ **не качать параллельно**: 4 потока получают бан и половину ошибок. Только
  последовательно, `sleep 2–3` между файлами.

Так восстанавливаются волонтёрские транскрипции приходских книг, выложенные когда-то
школами, краеведами и частными сайтами.

## 2. SPA-портал: найти настоящий бэкенд

Симптом: любой `/api/...` путь отдаёт 200 и **один и тот же HTML** (оболочку приложения),
`json.load` падает на первом символе.

```bash
curl -sSL https://<host>/ -o page.html
grep -o 'src="[^"]*\.js"' page.html            # найти main.<hash>.js
curl -sSL https://<host>/main.<hash>.js -o main.js
grep -oE '"/[a-zA-Z0-9_/{}.-]*(api|search|internal)[a-zA-Z0-9_/{}.-]*"' main.js | sort -u
grep -oE '.{0,40}serverUrl.{0,120}' main.js | sort -u    # базовый префикс + маршруты
```
Из бандла достаются: базовый префикс API, точные пути, имена полей запроса.
Дальше обычный `POST` с `Content-Type: application/json`.

## 3. Большие файлы с облачных дисков

Обычная ссылка `uc?export=download&id=…` на файлах >100 МБ возвращает HTML
«Virus scan warning». Надо вынуть из него токен и запросить:
```bash
uuid=$(grep -o 'name="uuid" value="[^"]*"' warn.html | sed 's/.*value="//;s/"//')
curl -L "https://drive.usercontent.google.com/download?id=<ID>&export=download&confirm=t&uuid=$uuid" -o file.pdf
```

## 4. Ложная недоступность: TLS вместо блокировки

`curl` возвращает **000** на государственном ресурсе. Это чаще всего **сертификат
национального УЦ**, отсутствующего в стандартном CA-bundle, а не блокировка.
Симптом: `openssl s_client` → `unable to get local issuer certificate`.
**Лечение:** `curl -k` (или доустановка корневого сертификата).

👉 Общее правило: **проверять TLS отдельно от сети**, прежде чем записывать ресурс в мёртвые.

## 5. Асимметрия маршрутов

Доступность зависит от того, из какой страны идёт запрос. Один и тот же портал может
открываться с машины в одной юрисдикции и молчать с другой — и наоборот.
Прежде чем чинить коннектор или объявлять портал мёртвым — **прогнать с обеих точек**.
Практический вывод: держать под рукой два выхода (например, SSH-туннель `ssh -D`
и локальный curl) и вести таблицу «хост → откуда открывается».

## 6. Рендер и просмотр книг

```bash
pdfinfo book.pdf | head                        # число страниц, разворот или страница
pdftoppm -f N -l N -r 110 -jpeg -singlefile book.pdf out/pg-N
pdftoppm -r 150 -jpeg book.pdf out/p           # 150 dpi: разворот ~5000×4000, текст читаем
convert p-NN.jpg -resize 2000x -normalize view.jpg
```

**Определить геометрию ДО чтения:** `identify` на файле **из середины** дела, а не на первом
(первый — обложка, у неё другой размер). Отрендерить один кадр целиком и глазами посчитать
страницы. Признак разворота — ландшафтная пропорция и линия сгиба посередине.
Симптом ошибки: «пропуски» в сквозной нумерации записей при подряд идущих кадрах —
значит читается не весь лист.

**Обзор большой книги без указателя:**
```bash
# верхние полосы всех разворотов = хронология книги
convert p-NN.jpg -crop 100%x8%+0+40 +repage top-NN.png
montage top-*.png -tile 1x28 -geometry +2+2 years.jpg
# титулы десятка дел разом
montage title-*.jpg -tile 3x3 -geometry +6+6 titles.jpg
```

## 7. 🔑 Поиск по колонке деревни (главный приём для метрик XIX в.)

В приходских книгах XIX в. слева от каждой записи стоит **название деревни** и номер записи.
Текст читать не нужно — достаточно вырезать левую колонку каждой полустраницы:

```bash
W=$(identify -format %w pg.jpg); H=$(identify -format %h pg.jpg)
HW=$((W/2)); CW=$((HW*24/100))                  # 24% полуширины
convert pg.jpg -crop ${CW}x${H}+0+0    +repage -resize x1500 col-L.png
convert pg.jpg -crop ${CW}x${H}+${HW}+0 +repage -resize x1500 col-R.png
montage col-*.png -tile 10x2 -geometry +6+6 -background '#888' mont.jpg
```
Книга в 90 разворотов = **9 монтажей вместо 174 чтений**. На монтаже видно название деревни
вместе с номером записи ⇒ дальше открывается только нужная страница.

Тот же приём работает для любой книги с постоянной левой колонкой (топоним, № двора, сословие).

## 8. Кроп спорного слова

- 🔑 кропать в **нативном** разрешении или увеличивать **≤ ×1.7** (LANCZOS).
  `-resize` вверх размывает рукопись и порождает ложные чтения;
- для рукописей с водяным знаком поверх текста помогает разделение каналов:
  `convert кадр.jpg -channel B -separate -level 9%,73% -unsharp 0x1.4 out.jpg`
  (тёплые чернила темнеют в синем канале, нейтрально-серый знак светлеет);
- кроп задавать **в пикселях** с `+repage`: проценты в ImageMagick прыгают.

## 9. OCR: когда стоит и когда нет

- в системе обычно только `eng`; языковые модели берутся из общедоступных наборов
  `tessdata_fast` и подключаются через `TESSDATA_PREFIX`;
- ⚠️ на скане 250 dpi — **1–2 минуты на страницу**. Если страниц меньше полусотни,
  читать глазами быстрее, чем распознавать;
- рукописи XVII–XVIII вв. OCR **не берёт вообще** — там только чтение (см. скилл `skoropis`);
- машинописные описи XX в. — наоборот, идеальный кандидат: `pdftotext -layout` + `grep`.

## 10. Греп по фамилии: диакритика и варианты

Список «готовых» написаний фамилии **всегда неполон**. Строить **шаблон**, а не перечень:
```
Z[ao][lł][ea][nń][ie][ec]        вместо  Zalenec|Zalency|Załeniec|…
```
- польские, литовские, латышские формы содержат диакритику, которой нет в списке;
- кириллические и латинские формы одного рода ищутся **отдельно**;
- женские формы: `-owa` = замужняя (жена N), `-owna` = дочь N — это разные люди;
- фамилия **рвётся переносом строки** («Petri Elz-|but») — грепать по обеим половинам;
- регулярка по корню промахивается на беглой гласной («сорочк» не ловит «сорочек») —
  проверять на заведомо известном примере.

⚠️ `ugrep` не поддерживает `(?!…)` и падает на `.{0,90}` в юникод-контексте
(«exceeds complexity limits») — сложные шаблоны прогонять через `python3 -c`.

## 11. Сессии и куки пользователя

- когда ресурс требует логина, работать **сессией владельца аккаунта**, переданной им
  добровольно (кука/Bearer), и уничтожать её после работы (`shred -u`);
- никогда не сохранять чужие пароли; кука живёт часы — это достаточно;
- действия, создающие обязательства (заказ, оплата, отправка запроса), выполняет **человек**.
  Автоматизировать можно только обратимое: сбор корзины, поиск, скачивание.

## 12. Проверка «оцифрован ли фонд» одним запросом

Во многих порталах карточка дела достаётся по предсказуемому ID:
```
findById?id=<АРХИВ>_<фонд>_<опись>_<дело>
```
Пустая карточка (все поля `None`) = такого дела в портале нет.
⚠️ **Обязателен контроль**: тот же запрос на заведомо существующем деле должен вернуть данные.
Без контроля «пусто» ничего не доказывает.

## 13. Хранение

- сканы книг — сотни МБ; отработанное выгружать в облако (`rclone`), оставляя рабочее;
- ⚠️ **не хранить в `/tmp`** — эфемерен, теряется между сессиями вместе с уникальными
  копиями из Wayback. Всё найденное сразу класть в постоянную папку рода;
- имена файлов самодокументирующие: `ТИП-ИМЯ-ДАТА-роль-место-источник-лист.jpg`.

### Выгрузка в облако, которой можно доверить удаление

Диск кончается раньше, чем поиск. Но выгрузка — та операция, где ошибка необратима,
поэтому она строится вокруг **сверки, а не вокруг завершения команды** (`PITFALLS.md` §5).
Порядок, отработанный на 35 тысячах файлов и 30 ГБ:

1. **Одна папка за раз**, `--transfers 2 --checkers 4 --tpslimit 4`. Параллельные заливки
   роняют API облака целиком.
2. После каждой папки — **пересчёт объектов на той стороне** и сравнение с локальным:
   ```bash
   loc=$(find "$d" -type f | wc -l)
   cl=$(rclone size "$DST/$d" --json | python3 -c 'import sys,json;print(json.load(sys.stdin)["count"])')
   [ -n "$cl" ] && [ "$cl" -ge "$loc" ] && echo OK || echo "НЕДОСТАЧА: $cl из $loc"
   ```
3. При недостаче или молчании облака — папка **пропускается нетронутой**, до 6 повторов
   с паузой. Молчание облака трактуется как недостача, не как успех.
4. Удаление — отдельным проходом и **только образы**: `.jpg/.png/.tif/.pdf/.cr3/.zip`.
   Отчёты, реестры и скрипты весят килобайты и остаются на диске: без них следующая
   сессия начинает вслепую.
5. Итог писать в файл-карту рядом с данными (`_FILES-IN-<где>.md`): куда уехало,
   команда возврата одной строкой, объёмы по папкам.

Нормально, если в облаке файлов **больше**, чем локально: там накоплены прошлые выгрузки,
включая давно удалённое. Тревожный случай ровно один — в облаке меньше.


## Неполная цепочка сертификатов: издателя берут из самого сертификата

Симптом: `unable to get local issuer certificate`, хотя корневой сертификат нужного
удостоверяющего центра вы уже добавили. Причина не в вас — **сервер не досылает
промежуточный сертификат**, а тот, что лежит по общеизвестному адресу УЦ, успел
устареть (у национального УЦ РФ, например, промежуточных несколько поколений).

Адрес актуального издателя записан в самом сертификате сайта, в расширении
Authority Information Access:

```bash
# вытащить сертификат сайта и прочитать, кто и где его издатель
curl -sk https://<сайт> -o /dev/null -w "%{certs}" > leaf.pem
openssl x509 -in leaf.pem -noout -text | grep -o 'CA Issuers - URI:[^ ]*'
#   CA Issuers - URI:http://<цдп>/cdp/subca_ssl_rsa2024.crt

# скачать издателя и собрать свой бандл, НЕ трогая системное хранилище
curl -fsS <адрес издателя> -o sub.crt
openssl x509 -inform DER -in sub.crt -out sub.pem 2>/dev/null || cp sub.crt sub.pem
awk 1 /etc/ssl/certs/ca-certificates.crt root.pem sub.pem > bundle.pem   # awk 1 даёт перевод строки
SSL_CERT_FILE=$PWD/bundle.pem python3 scripts/archnet.py probe https://<сайт>
```

Сверить, тот ли издатель: `Authority Key Identifier` листа обязан совпасть с
`Subject Key Identifier` промежуточного.

⚠️ Отдельный бандл лучше установки в систему: ничего не меняется на машине, действует
только для ваших запросов, удаляется одним файлом.

⚠️ **Третий случай, который выглядит так же, но лечится иначе:** сертификат выписан
на ДРУГОЕ имя (хостинг отдаёт свой дефолтный, сайт переехал с прежнего домена).
Проверить: `openssl x509 -in leaf.pem -noout -subject`. Никакой бандл тут не поможет —
либо `http://`, либо осознанно снять проверку имени.


## Поиск, спрятанный за POST: как найти его и как вызвать

Симптом: страница поиска открывается, в адресной строке видны параметры, но **в HTML
результатов нет** — счётчик пуст, карточек одна-две. Значит выдачу подставляет скрипт,
и ссылкой её не получить.

**1. Найти внутренний шлюз в бандле.** Он почти всегда назван глобальной переменной,
а не зашит в вызов:
```bash
curl -s https://<портал>/<страница поиска> -o page.html
grep -oE '(src|href)="[^"]+\.js[^"]*"' page.html          # какие бандлы грузятся
curl -s https://<портал>/<бандл>.js -o app.js
grep -oE 'window\.[A-Za-z_]*(Gate|Api|Url|Ip)[^;]{0,80}' app.js   # window.XxxGate="/путь/"
grep -oE '"[^"]{0,60}(_search|/api/|ajax)[^"]{0,60}"' app.js | sort -u
```
Ищите рядом функцию отправки: `method:"POST", url: ... + window.XxxGate + "?builder="+…`
Она же покажет **форму тела запроса** — состав полей.

**2. Отсечь ложные следы.** В бандле обычно лежат и мёртвые, и внутренние адреса:
отдельный хост `request.<портал>` может не резолвиться, а `ELASTIC_PULL=["10.x.x.x:9200"]`
— внутренний адрес, снаружи закрытый. Рабочим оказывается путь **на том же хосте**.

**3. Вызвать:**
```bash
python3 scripts/archnet.py post "https://<портал>/<шлюз>?builder=<Тип>" \
  --json '{"builderType":"<Тип>","queryFields":{"last_name":"<Фамилия>"},
           "filterFields":{},"indices":["<индекс>"],"entities":[],"from":0,"size":10}'
```
Заголовок `Referer` со своего же сайта подставляется сам — без него часть шлюзов даёт 403.

**4. Что ждать в ответе.** Под такими шлюзами обычно Elasticsearch: `hits.total` — сколько
всего, `hits.hits[]._source` — сама запись. У военных и учётных картотек в `_source`
лежат **место рождения (губерния, уезд, волость), чин, часть и полный архивный шифр**
(фонд, опись, дело, коробка) — то есть именно то, ради чего идут в базу.
Ссылка на карточку часто собирается как `<портал>/<раздел>/<_type><id>/`.

⚠️ Не перебирать поля наугад: **пустой `entities` возвращает всё, а неверный — ноль**.
Ноль записей при заполненном фильтре — сначала проверьте на заведомо частой фамилии.


## Темп запросов: читать как человек, а не как робот

У региональных архивов доступ к образам **платный** (подписка, электронный читальный зал,
поштучная оплата копий). Поэтому они считают запросы и блокируют скорость, непохожую
на человека — портал архивов Санкт-Петербурга, например, банит за серию обращений,
и снимается это не сразу.

Причина соблюдать темп не в том, что «иначе поймают». Массовая выгрузка оплаченного
доступа — это его обход: архив продаёт просмотр, а не копию фонда. Быстрее человека
читать никто не разрешал.

**Правила, которые реально работают:**

| Правило | Почему |
|---|---|
| один поток, запросы по очереди | параллельные соединения — первый признак робота |
| пауза 3–6 секунд у платных архивов, 1–2 у открытых | и с разбросом: ровные интервалы видно сразу |
| страницы качать по мере чтения, а не «всё дело целиком» | цель — прочитать конкретные листы, а не собрать копию фонда |
| одна сессия, одни куки, не переоткрывать вход | смена сессии на каждый запрос выглядит как обход счётчика |
| дневное время, а не ночь | «ночью не заметят» — миф: именно ночная активность и выделяется |
| получили 429 или внезапный 403 — **остановиться** | повтор превращает ограничение в блокировку аккаунта |

```bash
# по умолчанию пауза уже соблюдается; у платных архивов она увеличена
python3 scripts/archnet.py af https://<архив> "<запрос>"

# ещё медленнее — когда работаете с образами, а не с описями
python3 scripts/archnet.py --delay 8 af https://<архив> "<запрос>"
```

⚠️ Скрипт сам держит паузу между обращениями к одному хосту и предупреждает при 429/403.
Но он не помешает вам запустить пять копий разом — а это ровно то, за что блокируют.

⚠️ Скачанное платным доступом остаётся у вас: не выкладывать образы в общий доступ
и не пересылать дальше. Ссылку на дело — сколько угодно, это как раз полезно.

## Сотни кадров одной книги: дайджест вместо пролистывания

Актовая книга ЗАГС или метрика — это 300–1100 кадров, где на каждом кадре нужны
две-три строки. Смотреть их по одному разорительно. Приём: из каждого кадра вырезать
**только полосы с нужными графами** и склеить сеткой 3×4 — 500 кадров сводятся
к 40 картинкам, и фамилия читается так же уверенно, как на полном кадре.

`scripts/zags_digest.py <папка> <выход> [y0 y1 y2 y3] [even]`
Две полосы: первая — фамилия и имя (ребёнка / умершего), вторая — строка родителей
или супругов. Доли высоты подбираются по одному развороту: открыть любой кадр целиком,
прикинуть, на какой высоте лежит графа, задать интервал с запасом ±3 %.

Ловушки, каждая стоила времени:
- **Доли плавают между книгами.** Бланк 1920 г. и бланк 1922 г. — разные; полосы,
  подобранные на одной книге, на другой режут пустоту. Проверять на первом же листе.
- **Кадры одной книги бывают разной высоты** (лист меньше, поля шире). Брать полосу
  шире, чем кажется нужным: `0.42–0.57` вместо `0.46–0.52`.
- **Один акт может занимать два кадра** — лицо и оборот. Тогда половина ячеек дайджеста
  пустая, это нормально; но если чётность сбилась (вставлен лишний кадр), фильтр `even`
  начинает показывать одни обороты. Проверять глазами на каждой сотне.
- Колонка родителей смещена вправо от колонки ребёнка — брать `x` от 0.28 до 0.97,
  иначе левый край названия деревни срезается.

## Границы разделов книги: вкладыш ищется по яркости, а не по пустоте

Многие книги ЗАГС сшиты из нескольких сельсоветов, и архив вложил перед каждым
разделом лист с названием. Найти их автоматически — значит не листать книгу целиком.

`scripts/find_dividers.py <папка>` — ищет кадр с почти пустым **центром**.
Считать долю тёмных пикселей по всему кадру бесполезно: скан лежит на чёрном фоне,
и рамка даёт те же 11 %, что и плотный текст. Смотреть надо область `a[40:340, 30:270]`
уменьшенного до 300×380 кадра.

Второй признак надёжнее первого: **вкладыш ярче страницы**. У бумаги книги яркость
185–200, у архивного вкладыша 210–240. Если книга бледная (карандаш, выцветшие чернила)
и порог по тёмным пикселям ловит сотни ложных, отбирать по `c.mean() > 215`.

⚠️ Надпись на вкладыше может не совпадать с описью: в ГАНО вкладыш «Щукинский с/совет»
надписан от руки «Покровский», и записи под ним — Покровского с/с. Прежде чем читать
раздел, сверить название на вкладыше с шапкой первого же акта.

## Когда вкладышей нет: сельсовет читается из шапки акта

`scripts/headers_scan.py <папка> <выход> [шаг] [y0 y1]` — берёт каждый N-й кадр
и вырезает строку «Отдел ЗАГС при … с/совете». Шаг 4–6 достаточен, чтобы поймать
границу раздела с точностью до пары актов, дальше уточняется вручную.

Тот же приём работает на печатных справочниках: у «Списка населённых мест» колонтитул
называет округ и район, поэтому нужный разворот в книге на 800 страниц находится
десятком проб с шагом 50, а не просмотром оглавления.

## ГАТО (archtomsk.tomica.ru): каталог и образы

Движок КАИСА, но параметры отличаются от ГАНО.

**Поиск по заголовкам дел** — два шага, куки обязательны:
1. `GET /search?type=custom&searchObjectType=DOCUMENTS&p3.v=<текст>&p3.c=12&p3.a=1512`,
   сохранить cookie jar, из HTML взять `data-search-index`.
2. `GET /ajax/tree/<idx>?page=1&nPage=1&size=20&id=1054_0_3&parentId=0&objectType=1156&showPageList=false&completeWorkId=-1`

⚠️ Ключ ко второму шагу — литерал `id=1054_0_3`. Без него сервер отвечает 400
(«Required Long parameter 'parentId' is not present»), а с `parentId=0&objectType=1156`,
но без этого `id`, возвращает пустой массив `[]` — то есть выглядит как «ничего не найдено»,
хотя дела есть. Ответ — JSON-массив, заголовок дела лежит в HTML внутри поля `text`.

**Карточка дела**: `GET /ajax/obj/<treeId>/<idx>?children=true` — JSON со всеми
атрибутами: шифр, заголовок, количество листов, крайние даты, старый номер,
раздел описи. Там же `linkButtons` с готовым адресом подачи требования:
`/private/office/ask?ak=1&aot=1&oid=&action=askdata.createNewASK&field_document=<treeId>`

**Есть ли у дела образы**: смотреть список `groups` в карточке. У неоцифрованного дела
это только «Старые номера», «Тематические группировки», «Персоны», «География», «Языки»,
причём почти все с `empty: true`. Группы с записями образов там просто нет.
Так проверяется за один запрос, без попыток скачивания.

**Скачивание образов (нужна сессия читателя с оплаченным доступом):**
1. `GET /private/imageViewer/show?objectId=<id>&attributeId=<attr>&serial=<n>&group=<g>&ext=.jpg`
   с `JSESSIONID`. Если вернулось ~900 КБ HTML без редиректа на /login — доступ есть.
2. В этом HTML лежит JS-массив с обфусцированными адресами страниц (имя массива
   случайное, ищется по шаблону `img.src = hostPath + '/image?url=' + <ИМЯ>[pageNum - 1]`).
   Длина массива = число страниц дела.
3. Каждая страница: `GET /private/imageViewer/image?url=<строка из массива>` →
   JPEG порядка 1–1,5 МБ, 2086×3000.

⚠️ `hostPath` в этом движке — не корень сайта, а `origin + "/private/imageViewer"`.
Запрос к `/image?url=…` даёт 500 с «Exception: null», и это выглядит как проблема
кодирования строки, хотя дело только в пути. Строку из массива передавать как есть.

## КАИСА, вариант с `private_api`: объём оцифровки одним запросом

Часть установок движка (проверено на областном архиве с платным абонементом) поверх описанного выше отдаёт
JSON-API личного кабинета. Он ценен одним: **говорит, сколько кадров дела реально снято,
до всякой попытки скачивания** — и снимает самую дорогую ошибку планирования
(`PITFALLS.md` §7).

```bash
# сколько образов у дела на самом деле
curl -s --socks5-hostname 127.0.0.1:11080 -A "$UA" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -H "Origin: https://$HOST" -H "Referer: https://$HOST/private/documents" \
  --data-raw '{"objectId":745544132,"languageId":1}' \
  "https://$HOST/private_api/get-object" |
python3 -c 'import sys,json; v=json.load(sys.stdin)["value"]; \
print(v["name"], v["groupRecordCounts"].get("4688"))'
```

- `groupRecordCounts["4688"]` — число оцифрованных кадров (группа образов; номер группы
  на другой установке может отличаться, берётся из карточки).
- `0` — образов нет вовсе, только заказ копий.
- Число, несопоставимо малое против листов дела (2–50 при тысяче листов), — **чужие
  заказные копии отдельных листов**, а не дело.
- Поиск по шифру: `POST /private_api/get-object-list` с
  `{"objectTypeId":4220,"searchParams":[{"attributeId":6725842,"searchConditionId":12,
  "value":"Ф. 301 Оп. 5 Д. 827"}],"attributes":[6725842,4894,4952,4920]}` — отдаёт
  `objectId`, заголовок, крайние даты.
- Токен живёт около суток, берётся из запроса браузера в кабинет; держать в файле 600,
  не в коде. Проверка живости доступа — запрос просмотрщика к заведомо оцифрованному
  делу: `200` — доступ есть, `302` на `/subscription` — **лимит выбран**, `401` — токен протух.

⚠️ `private_api` продолжает отвечать и после исчерпания абонемента — то есть проверять
оцифровку и строить план можно, когда качать уже нельзя. Это удобно: разведку делать
в «бесплатном» состоянии, а оплаченное время тратить только на выкачивание.

## Карта незнакомого дела: пробные кадры с шагом

Дело на две-три тысячи кадров без внутренней описи не охватить ни сплошным просмотром,
ни угадыванием. Приём: выкачать **каждый сотый кадр** в обзорном разрешении, склеить
верхние полосы в мозаику и прочитать шапки — получается соответствие «кадр → селение».

```bash
for n in $(seq 100 100 2700); do fetch_frame "$n" probe/ & done; wait
python3 scripts/archimg.py montage map.png 'probe/*.jpg' --tile 3x4 --label
```

На деле 7-й ревизии 2 773 кадра это дало за один заход: кадры 100–500 — город,
с 600 пошли селения уезда по алфавиту (на «А» кадр 600, на «Б» 700–800, на «К» 1700,
на «Н» 2600), а на 2740 алфавит дошёл до «О» и дело кончилось — значит селение на «У»
лежит **в другом томе**, и искать его в этом деле бесполезно.
Тот же приём находит и границы приходов внутри сборной книги метрик.

Шаг подбирать по плотности: 100 — для дела в тысячи кадров, 20 — чтобы поймать границу
конкретной сказки, 5–10 — когда участок уже локализован и нужен точный первый лист.

## Сторонний индекс описей: то, чего нет в поиске самого архива

У крупных архивов рядом с официальным каталогом живут **независимые указатели**,
набранные исследователями вручную с тех же описей. Они выигрывают в трёх вещах:
ищут по подстроке в заголовке дела (официальный поиск часто требует точной формы),
показывают дела **независимо от того, оцифрованы ли они**, и отдают результат таблицей
с колонкой о наличии сканов. Официальный сканопортал показывает только оцифрованное —
и потому отвечает «нет», когда дело существует, но лежит бумажным.

Такой указатель обычно устроен как GET-форма без авторизации:

```bash
# три условия И по заголовку + фильтр по годам, только оцифрованные
curl -sS "https://<индекс>/?title=<селение>&title3=<тип книги>&year_start=1825&year_end=1848&online=1"
# опись фонда целиком одним PDF
curl -sS "https://<индекс>/opisi_pdf/?fond=<фонд>"
```

Поля снимаются с разметки формы одной строкой — они и есть документация протокола:

```bash
curl -sS "https://<индекс>/" | grep -oE '<(input|select)[^>]*name="[^"]+"' |
    grep -oE 'name="[^"]+"' | sort -u
```

Искать в таком указателе следует **по селу прихода, а не по своей деревне**: в заголовок
дела попадает церковь и её село, деревни прихода в нём не перечислены.

## Запрос в ЗАГС: «иные сведения» надо требовать отдельно

Записи актов ХХ века переведены в электронный реестр **без графы «иные сведения»** —
оцифровывали только обязательные поля. Поэтому стандартная справка возвращает то, что
и так известно, а место жительства, занятие, семейное положение, причина смерти и срок
проживания остаются в бумажной книге и в ответ не попадают.

Что с этим делать:

1. Подавать отдельное заявление на **внесение иных сведений** в реестр — по нему
   сотрудник поднимает бумажную актовую книгу. Часто это делается электронным
   обращением исполнителя (дни) вместо бумажного заявления (до месяца).
2. Формулировать как **«все иные сведения, содержащиеся в записи»**. Перечисление
   нужных полей сужает ответ ровно до перечисленного.
3. Проверять полученный бланк: в каждом пункте должен стоять либо текст, либо прочерк.
   **Пустой пункт означает, что его не смотрели**, — основание просить доработку.
4. Знать, где физически лежит книга: реестр называет орган регистрации, а бумажные
   книги могли переехать в единое хранилище — письмо в прежний отдел уйдёт в пустоту.

Приём переносится на любой запрос в архив: требовать не выписку, а полный состав
записи, и считать пустое поле в ответе непроверенным, а не отсутствующим.
