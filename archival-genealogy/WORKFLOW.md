# Порядок работы и дисциплина фиксации

---

## 1. Старт нового рода

1. Собрать **исходные точки**: ФИО, приблизительная дата и место рождения, конфессия,
   сословие, любые семейные предания (пометить как предания).
2. Прогнать по **именным базам XX века** — они дают место рождения.
3. Определить административную и **церковную** привязку места: уезд/повет, волость, приход.
   Волость ≠ приход. Приход определяется по справочникам, картам с наложением и спискам НП.
4. Составить **список всех сохранившихся книг прихода** с годами, шифрами и статусом
   доступа. Этот список — рабочая карта на весь поиск.
5. Проверить наличие **транскрипций и указателей** по этому приходу.
6. Только после этого открывать сканы.

---

## 2. Файлы рода

| Файл | Что внутри |
|---|---|
| `<РОД>-search-<дата>.md` | **журнал**: пронумерованные дополнения, хронология, цитаты из документов, отрицательные результаты, калибровки книг, собственные поправки |
| `<РОД>-PERSONS-REGISTRY.md` | **реестр персон**: строка = персона + документ + путь к образу |
| `RODOSLOVIE-<РОД>.md` | поколенная роспись связным текстом с опорой на реестр |
| `PLAN-<РОД>.md` | приоритеты с номерами: шаг, адрес (шифр), что даст, чего НЕ даст |
| `START-HERE-<РОД>.md` | точка входа для новой сессии: состояние на сегодня, ключевые приёмы, чем заняться первым делом |
| `SOURCES-REGISTRY.md` | что где лежит и как достаётся — обновлять при каждом новом коннекторе |

🔑 Устройство реестра персон, правила отождествления и процедура аудита — `REGISTRY.md`.
Без него реестр вырождается в список имён без доказательств.

**Знаки достоверности:** `[Д]` документ + образ · `[Д•]` документ без образа ·
`[П]` печатный источник · `[G]` только вторичная база · `[Р]` реконструкция ·
`[?]` упомянут, своих данных нет.

**Нумерованные дополнения в журнале** («Дополнение 47») — чтобы на них можно было ссылаться
из плана и реестра. Каждое дополнение отвечает на вопрос: что искали, что нашли,
**что это закрывает**, куда ведёт дальше.

## 3. Как выглядит одна итерация

```
Гипотеза → адрес (шифр/URL) → проверка → запись результата (в т.ч. отрицательного)
→ обновление плана → следующий приоритет
```

Каждый шаг плана описывается тремя строками:
- **что делаем** (шифр, URL, книга, годы);
- **что даст**, если найдётся;
- **чего НЕ даст** — это отсекает половину лишней работы.

---

## 4. Когда остановиться и переключиться

- вопрос закрыт первой находкой — не дочитывать книгу;
- три источника подряд по одной линии дали пусто — сменить тип источника, а не глубину;
- стоимость следующего шага (сплошной просмотр) превышает ценность ответа — записать
  как «марафон» в план и заняться дешёвыми ветками;
- появился новый географический или именной ключ — перепроверить им **уже просмотренные**
  источники: старый негатив мог быть следствием неверного ключа.

---

## 5. Передача работы человеку

Часть шагов исследователь физически не может выполнить: платный доступ, запрос в архив,
портал, закрытый для иностранных IP, оплата копий, поездка в читальный зал.
Для них готовится **точный адрес**: архив, фонд, опись, дело, листы, что именно смотреть,
и как выглядит искомая запись. Это самостоятельный результат работы — часто более ценный,
чем ещё один просмотренный скан.

Шаблон запроса в архив:
```
Архив, фонд N, опись N, дело N, листы N–N.
Прошу: скан/копию листов ... либо выписку о наличии записи о <событие> <лицо> <годы>.
Основание поиска: <какой документ указывает на это дело>.
```

---

## 6. Этика и границы

- в родословную идёт только подтверждённое; предположение помечается как предположение;
- чужие персональные данные (живущие люди, заказчики, третьи лица) не выносятся
  в общие файлы и не публикуются;
- внешние системы — **только чтение**; ничего не создавать и не изменять в чужих базах;
- действия с обязательствами (заказ, оплата, отправка) выполняет человек.
