# Реестр персон: как вести и как перепроверять

Реестр — не древо и не рассказ. Это **промежуточный слой между документом и родословной**,
единственное место, где каждая строка привязана к листу дела. Без него поколенная роспись
через месяц становится непроверяемой: помнить, откуда взят каждый факт, невозможно.

Три слоя, и они не смешиваются:

```
документ (образ, шифр)  →  СТРОКА РЕЕСТРА (что написано)  →  роспись (кто кому кем приходится)
```

Ошибка, которая губит работу: писать сразу третий слой. Тогда гипотеза отождествления
попадает в текст как факт и через полгода неотличима от документа.

---

## 1. Единица записи — упоминание, а не человек

**Строка реестра = одно упоминание в одном документе.** Один человек даёт столько строк,
сколько раз встретился: рождение, венчание, три ревизии, исповедная роспись — шесть строк.

Почему так, а не «одна строка на человека»: отождествление («это тот же Иван») —
**вывод, а не наблюдение**. Если сливать упоминания сразу, ошибочное отождествление
исчезает из виду и его нельзя пересмотреть. При раздельных строках достаточно поменять
поле `persona`, документы остаются нетронутыми.

## 2. Поля строки

| Поле | Что в нём | Правило |
|---|---|---|
| `id` | номер упоминания, сквозной | не переиспользовать даже после удаления |
| `persona` | к какой персоне отнесено (`ROD-014`) | пусто, пока отождествление не обосновано |
| `имя_в_документе` | **дословно**, с орфографией источника | «Куземко Квашнинъ», не «Кузьма Квашнин» |
| `имя_норм` | приведённое к современной форме | отдельное поле, чтобы не потерять оригинал |
| `пол` | м/ж | из формуляра, а не из имени |
| `роль` | в записи: младенец, отец, мать, восприемник, жених, поручитель, глава двора | восприемники и поручители — **круг семьи**, не мусор |
| `событие` | рождение/крещение, брак, смерть, перепись, ревизия | |
| `дата_в_документе` | как написано | «Ѱкв году», «die 10 Apr.» |
| `дата_норм` | ISO, с пометой стиля | старый стиль помечать; год от сотворения мира минус 5508 |
| `возраст` | если указан | ⚠️ возраст ≠ год рождения, см. §4 |
| `место` | селение, приход, волость, уезд | топоним пишется устойчивее фамилии — это ключ |
| `сословие` | крестьянин, мещанин, шляхтич, духовное | определяет, в каком фонде искать дальше |
| `отец`/`мать`/`супруг` | **как названы в этом документе** | «Ивановъ сынъ» — это отчество-документ, а не ссылка на персону |
| `шифр` | архив, фонд, опись, дело, лист | без шифра строка недействительна |
| `образ` | путь к файлу или адрес кадра | для знака `[Д]` обязателен |
| `знак` | `[Д] [Д•] [П] [G] [Р] [?]` | см. `WORKFLOW.md` |
| `основание` | почему отнесено к этой персоне | заполняется вместе с `persona`, не позже |
| `журнал` | номер дополнения | обратная ссылка на ход рассуждения |

Формат — таблица Markdown или CSV; для больших родов удобнее CSV с тем же набором колонок.
Экспорт в GEDCOM делается **из** реестра, но истина остаётся в реестре: программы древ
не хранят ни шифра, ни основания отождествления.

## 3. Отождествление: когда два упоминания — один человек

Требовать **совпадения по нескольким независимым осям**, а не по имени:

| Ось | Вес |
|---|---|
| имя + отчество | низкий: в одной деревне полдюжины тёзок |
| место (двор, селение, приход) | высокий |
| сословие и владелец | высокий |
| имена родителей и супруга | высокий |
| непротиворечие возрастов и дат | обязательное условие, не довод «за» |
| соседи по двору, восприемники, поручители | средний, но независимый |

Правило: **одного совпадения не хватает никогда.** Отождествление без записанного
`основания` считается не сделанным. Если оси противоречат — не отождествлять и завести
две персоны; слить их дешевле, чем потом разделять разошедшуюся роспись.

⚠️ Однофамильцы в одном селении — норма, а не редкость. Особенно у шляхты, где фамилия
означала гнездо, и у крестьян по прозвищу отца.

## 4. Даты и возрасты — где чаще всего врут

- **Возраст в ревизии — не год рождения.** «40 лет в 1719» даёт ~1679 ±2–3: возраст писали
  округлённо и со слов. Записывать интервалом, а не точкой.
- **Возраст между двумя ревизиями обязан сходиться.** Расхождение больше 3 лет — сигнал:
  либо это другой человек, либо одна из записей прочитана неверно. Это самая дешёвая
  и самая эффективная проверка отождествления.
- **Год от сотворения мира**: вычитать 5508 (сентябрьский стиль — с оговоркой).
- **Старый стиль**: не «переводить» молча; помечать, иначе даты рождения и крещения разъедутся.
- **Дата крещения ≠ дата рождения**, дата погребения ≠ дата смерти. В поле `событие`
  писать то, что зафиксировано.

## 5. Перепроверка: аудит, который делается регулярно

Проводить после каждой большой порции работы и обязательно **перед тем, как показывать
результат человеку**. Ошибки копятся тихо.

| # | Проверка | Как ловится |
|---|---|---|
| 1 | у каждой строки есть шифр; у каждого `[Д]` — открывающийся образ | `registry_audit.py` |
| 2 | каждый факт росписи прослеживается до строки реестра, а та — до листа дела | выборка 10 фактов «наугад» |
| 3 | арифметика возрастов между ревизиями сходится | `registry_audit.py` |
| 4 | нет дублей: одинаковые имя+место+событие+дата под разными `id` | `registry_audit.py` |
| 5 | в росписи нет «вероятно», «по-видимому», «должно быть» без знака `[Р]` | греп по тексту |
| 6 | все `persona` имеют заполненное `основание` | `registry_audit.py` |
| 7 | отрицательные результаты записаны: какие годы просмотрены сплошь | сверка с журналом |
| 8 | при новом ключе (топоним, вариант фамилии) **пересмотрены прежние отождествления** | вручную |

```bash
python3 scripts/registry_audit.py <РОД>-PERSONS-REGISTRY.md
```

🔑 **Проверка «наоборот» — сильнейшая.** Взять готовое утверждение росписи и попытаться
опровергнуть его теми же документами: сойдутся ли возрасты, был ли человек жив к этой дате,
мог ли он быть в двух местах. Подтверждающий поиск находит подтверждения всегда — потому
что их ищет.

## 6. Что не делается никогда

- не переписывать строку задним числом «как правильнее» — исправление вносится новой строкой
  или явной пометкой, старое чтение сохраняется;
- не подставлять недостающее поле по аналогии с соседней записью;
- не переносить в реестр данные вторичных древ иначе как со знаком `[G]` — они не источник,
  а подсказка, где искать источник;
- не хранить в реестре персональные данные живущих людей вместе с архивными: живые —
  отдельный файл, и он не публикуется.
