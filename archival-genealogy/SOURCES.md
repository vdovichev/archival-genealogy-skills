# Карта источников

Легенда доступа: 🟢 открыто, берётся скриптом · 🟡 поиск есть, но нужен разбор/логин ·
🔵 только тексты/образы, поиска по людям нет · 🔴 доступ зависит от страны IP · ⚫ закрыто.

⚠️ Перед выводом «источник недоступен» — см. `PITFALLS.md`, раздел «Ложная недоступность».
🔑 Конкретные адреса (111 позиций по разделам и регионам) — в `CATALOG.md`.
🔑 Нет среды с оболочкой — `NOCODE.md`: половина коннекторов работает обычным GET,
у порталов оцифровки для этого есть OAI-PMH.
Здесь — **протоколы**: один разобранный движок открывает десятки архивов сразу.

## A. Россия — движки архивных АИС

Региональные архивы построены на нескольких типовых движках. **Один разобранный движок =
доступ к десяткам архивов.** Определять движок по URL и вёрстке, затем переиспользовать код.

### A.1. «Архивный фонд» (Yii, самый распространённый) 🟢
```
GET /archive/search?search=<q>&annotation=Y&morph=Y&from=&to=&digitalCopy=on
GET /archive1/unit/<id>   /archive1/inventory/<id>   /archive1/funds/<id>
```
- ищет **заголовки** фондов/описей/дел, не персоналии;
- `digitalCopy` в некоторых установках обнуляет выдачу — проверять с ним и без;
- у части архивов есть `/archive1/images` (образы), у части нет;
- каталог измеряется тысячами фондов и миллионами дел — искать топонимом.

Так работают архивы Вологодской, Ивановской, Архангельской, Ярославской и ряда других областей.

### A.2. «КАИСА» (Альт-Софт) 🟢
```
GET  /search?type=simple&p.0.v=<q>&p.0.c=1582&p.0.a=15868         # простой поиск
POST /search  type=custom&searchObjectType=DOCUMENTS&p0.a=1596&p0.c=12&p0.v=<q>
GET  /ajax/tree/<N>?page=..&size=20   → JSON строк «шифр / заголовок / даты»
GET  /ajax/pages/<N>?...              → последнее число = число страниц
```
- результаты в Nuxt-пейлоаде, 10 на страницу, пагинация обязательна;
- атрибуты полей различаются по инсталляции: № фонда / № описи / № дела / заголовок —
  подбираются один раз и переиспользуются;
- ⚠️ поиск **подстрочный** (короткий корень ловит чужие фамилии);
- ⚠️ индексируются **не все описи фонда** — прежде чем считать отсутствие результатом,
  проверить, индексирована ли нужная опись (запрос по № фонда + № описи).

Так работают: РГИА, ряд областных архивов, региональные порталы Альт-Софт.

🔑 **Вариант с `private_api` (личный кабинет).** На части установок — проверено на
`vladimir.kaisa.ru` (ГАВО-Владимир) — поверх этого есть JSON-API кабинета:
```
POST /private_api/get-object       {"objectId":<id>,"languageId":1}
POST /private_api/get-object-list  поиск по шифру, attributeId 6725842, condition 12
```
Ценность одна, но крупная: `value.groupRecordCounts["4688"]` даёт **точное число
оцифрованных кадров дела** — то, чего нет в карточке каталога, где «кадры» означают
листы единицы хранения. Это единственный способ отличить оцифрованное дело от чужих
заказных копий пары листов до начала работы (`RECIPES.md`, `PITFALLS.md` §7).
`private_api` отвечает и при исчерпанном абонементе, поэтому разведку и планирование
делают бесплатно, а оплаченное время тратят только на выкачивание образов.

### A.3. Портал архивов Санкт-Петербурга (Liferay) 🔴🟢
```
/infres/search?p_p_id=archiveStoreSearchPortlet
  &_archiveStoreSearchPortlet_query=<q>
  &..._searchInFields=on&..._searchInOcrTexts=on
  &..._startYear=&_endYear=&..._selectedArchives=&..._selectedSemanticTypes=
```
🔥 **`searchInOcrTexts` ищет ВНУТРИ распознанных сканов** — принципиально мощнее обычных АИС:
находит фамилию в машинописных описях и указателях. Семантические типы для метрик:
`MetricBook`, `MetricBookLutherans`, `MetricBookJew`, `BookZAGS`.
Опись: `/infres/-/archive/<abbr>/<фонд>/<опись>`, 20 ед. хр. на страницу.
🔑 Гонять **все варианты написания** фамилии: русская передача иностранных фамилий гуляет
с/з, е/э, и/і — разные написания дают разные наборы дел.

### A.4. Поисковики распознанных метрик 🟡
Крупные ИТ-компании и архивные проекты выкладывают **ИИ-распознанные** метрические книги,
ревизии и исповедные ведомости с поиском по тексту. Отдают: сниппет распознанного текста,
даты, архив + фонд-опись-дело + лист, идентификатор картинки.
- данные лежат в `__NEXT_DATA__` страницы результатов;
- ⚠️ пагинация: имя параметра подбирается опытом — неверное имя молча отдаёт первую страницу,
  и это легко принять за «пагинации нет». Смотреть эхо своего значения в `pageProps`;
- ⚠️ часть сервисов отдаёт 308-редирект — без `curl -L` не парсится;
- капча, если появляется, снимается кукой из браузера пользователя (не паролем).

### A.5. Заказ электронных копий 🟡

⚠️ Всё, что ниже, — доступ платный. Темп запросов держать человеческий,
выгрузку делом целиком не делать: см. `RECIPES.md`, «Темп запросов».
Порталы заказа копий (Bitrix и аналоги): сессия = кука из браузера пользователя.
Корзина формируется программно (обратимо), **оформление и оплата — только действие человека**.
Формула ID дела в описи нелинейна (в описи бывают пропуски) — сверять по `<title>` карточки.

## C. Агрегатор населённых пунктов и справочников 🟢

Открытый REST без авторизации (типовой набор эндпоинтов):
```
/api/v2/catalogs?page=N                     каталоги-справочники (сотни, миллионы записей)
/api/v2/settlements/<uuid>                  НП: координаты, привязка, соседи
/api/v2/persons?settlement=<uuid>           все персоны села
/api/v2/persons?surname=<X>                 персоны пользовательских древ
/knowledge-base/catalogs/<key>?surname=X    точный поиск внутри справочника
/api/v1/catalogs/<key>/records              ПЕРВИЧНЫЕ строки документов
```
Состав справочников: ревизские сказки, метрические, исповедные, списки НП, переписи, кладбища,
базы ПМВ и ВОВ, блокада, служилые люди, медицинские списки, списки избирателей.
Данные страниц — в `__NEXT_DATA__`. Пагинация поиска клиентская ⇒ **сужать запрос, а не листать**.
⚠️ Пользовательские древа — гипотеза, не источник.

## D. Литва 🟢 — самый открытый контур в регионе

### D.1. Национальный портал оцифровки (epaveldas.lt)
Витрина оцифровки: национальная библиотека, госархив, библиотеки университетов, музеи.
SPA — обычные `/api/...` пути отдают HTML-оболочку. Настоящий бэкенд:
```
POST /vepis-api/internal/find
     {"term":"...","page":0,"pageSize":100,"filters":{},"includeFullText":true}
GET  /vepis-api/internal/findById?id=<ID>
     → resourcesFull = прямые ссылки на ПОЛНОРАЗМЕРНЫЕ jpeg
POST /vepis-api/internal/advancedSearch          (расширенный)
```
- `includeFullText:true` = поиск по **OCR всей библиотеки** (печать, газеты, справочники).
  Идёт долго (до 1–2 мин на термин) — гнать по одному;
- фильтр по фондодержателю: `"filters":{"providerFacets_str":["<CODE>"]}` (коды видны
  в `facets` любого ответа);
- схемы ID: `<библиотека>01-*` рукописные отделы · `<АРХИВ>_фонд_опись_дело` · музейные · печать;
- **проверка «оцифрован ли фонд»**: `findById?id=<АРХИВ>_<ф>_1_1` — пустая карточка (все поля
  `None`) = фонда в портале нет. Обязательно с контролем на заведомо живом деле;
- ⚠️ у части архивных дел образов нет (`default.jpg` → 404): портал отдаёт только каталожную
  запись, а в `additionalData` лежит ссылка на закрытую архивную ИС;
- ⚠️ **две формы идентификатора** (`604/11/35` и `АРХИВ_1999_3_83`) — если одна даёт пусто,
  пробовать вторую;
- ⚠️ полнотекст ищет **только печать**: рукописи им не находятся. Рукописи ищутся
  по **описаниям** карточек, а описания составлены по имениям и учреждениям ⇒ искать топоним;
- 🔧 перебор фондов (`findById` для `<N>/1/1`) даёт карту: у каждого католического прихода
  свой фонд; отсутствие фонда прихода — признак, что книги в госархив не поступали;
- 🔧 перебор описи (`<Ф>/<О>/1..N`, поле `title`) заменяет недоступную опись.

### D.2. Волонтёрский архив метрик (genmetrika.eu) 🟢
- каталоги: крещения / браки / смерти / **смешанные книги** (легко пропустить) /
  списки прихожан и инвентари / описи приходов / поместья;
- 🔑 **текстовые транскрипции** приходских книг — по ним грепать вместо чтения скорописи;
- 🔑 встроенный поиск по всему сайту (freefind) мгновенно показывает, в каких транскрипциях
  встречается фамилия;
- страницы приходов содержат **описи церковных архивов** и историю сохранности — оттуда
  узнаётся, сколько книг вообще существовало;
- служит **указателем на внешние выкладки** сканов (районные библиотеки, школы, краеведы).

### D.3. Краеведческие порталы районных библиотек 🟢
Выкладывают метрические книги **целыми PDF** и постранично JPEG, бесплатно, без регистрации:
`/dokumentai/<id>-<slug>` → внутри прямая ссылка `img/<файл>.pdf`.
Перебор каталога — параметром `?start=0,20,40…`.
⚠️ У постраничных выкладок в URL бывают **пробелы** → `urllib.parse.quote`.
Это часто **единственный** открытый доступ к книгам XIX в., которых нет в госпортале.

### D.4. Цифровые коллекции университетских библиотек (IIIF) 🟢
Актовые книги судов, рукописные собрания:
```
GET /objects/<objectId>/manifest.json?format=rich      IIIF Presentation 3
кадр: items[i].items[0].body.id ; размер: /full/max/ → /full/1400,/
```
⚠️ OCR/TEI-слоя нет — только изображения. Ищется по описаниям коллекции.

### D.5. Государственная архивная ИС ⚫
Отдаёт 403 из-за облачной защиты для запросов не из страны. **Роль исследователя —
найти точный шифр** (через портал оцифровки, каталоги, печатные справочники) и передать
заказчику/родственнику в стране, который скачает сам.

## E. Беларусь 🟢🟡

### E.1. Сканы описей в открытом доступе 🟢
Архив выкладывает **описи** постранично: перечни вида `/fondi<от>-<до>` (шаг 100),
таблица «Фонд № | Опись № | Скачать», ссылка ведёт на облачный диск.
- скачивание с облака: `https://drive.google.com/uc?export=download&id=<ID>`;
- часть описей — **машинописные с текстовым слоем**: `pdftotext -layout` + `grep`
  находит нужное дело среди тысяч за минуту. Остальные — только образы;
- ⚠️ у больших фондов опись разбита на тома; **диапазон дел напечатан на титуле тома** —
  искать бинарным поиском по титулам, а не подряд;
- ⚠️ у части фондов заказ идёт по **делопроизводственному** номеру, а не порядковому:
  в описи две колонки номеров, в шифре стоит второй.

### E.2. Указатели метрических книг по губерниям 🟢
Таблицы «Приход | Годы | Фонд/Опись», отдельно православные/униатские и католические.
⚠️ Покрыты не все губернии — по остальным только описи.
🔑 Отсутствие прихода в католическом перечне при наличии в православном — довод о конфессии.

### E.3. Фондовый каталог 🟢
Быстрый поиск — **POST** с полем `search=<термин>` (⚠️ прямой GET с `%20` в пути даёт 403).
Ищет названия фондов и аннотации, **не персоналии**.
🔑 Полный список фондов берётся **не поиском, а листанием каталога**:
`/catalogue/<N>/`, `/catalogue/<N>/2/`, `/3/` … — названия фондов единственный способ понять,
какие фонды вообще стоит смотреть (перечни описей дают только номера).

### E.4. Печатные извлечения из актовых книг 🔵
Многотомные дореволюционные издания извлечений из актовых книг губерний, выложенные
краеведческими сайтами на облачных дисках.
🔑 Внутри бывают **поветовые своды выводов шляхты** — сотни родов с гербами, перечнями
предъявленных документов и поколенными схемами. Лучший быстрый ответ на вопрос «выводился ли
род как шляхта в таком-то повете».
⚠️ Отсутствие в своде ≠ отсутствие рода: вывод делали не все. Формулировать
«род не выводился в … в … гг. по опубликованному своду N родов».
⚠️ Текстового слоя обычно нет — читать печатный **указатель в конце тома**.

## G. Мировой каталог микрофильмов (FamilySearch) 🟡

Требует сессии владельца аккаунта (Bearer = значение сессионной куки; куки после работы
уничтожать `shred -u`).
```
GET /platform/users/current                     проверка сессии
GET /service/search/hr/v2/personas?q.surname=X&q.surname.exact=on&count=20
GET /service/search/catalog/search?q.keywords=<слово>&count=100&offset=N
```
🔑 **Главная ценность — не поиск людей, а каталог как карта шифров**: в описании микрофильма
указан точный архивный шифр («Volume 604-11/35»), который затем подставляется в национальный
портал оцифровки и даёт образы **бесплатно**.
🔑 Приходы Восточной Европы названы **по-русски в транслитерации ALA-LC** — искать по уездам
и по одному слову; фильтры по стране и месту часто не работают.
⚠️ Индексация неравномерна: католические метрики целых стран могут отсутствовать,
а поиск по фамилии выдавать только эмигрантов.

## I. Чаты и сообщества как источник 🔵

Выгрузки региональных генеалогических чатов (сотни тысяч сообщений) — это:
- готовые **шифры дел**, найденные другими исследователями;
- ссылки на источники, которых нет ни в одном каталоге;
- живые подсказки о доступности и о том, «где на самом деле лежит».

Обрабатывать как корпус: извлекать домены, шифры вида «ф. N оп. N д. N», ссылки, топонимы.
