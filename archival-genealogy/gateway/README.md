# Шлюз: как дать ассистенту в браузере доступ к закрытым архивам

Ассистент в браузере ходит с зарубежных серверов и не умеет ни прокси, ни POST-запросов.
Шлюз решает обе задачи: он стоит на дешёвом сервере в нужной стране, принимает обычный
GET и возвращает страницу архива.

```
чат → http://<ваш сервер>/g/<секрет>?url=<адрес архива> → архив
```

Нужен, только если источники закрыты по географии. Проверьте сначала `../NOCODE.md`:
половина каталога открывается и без всего этого.

## Установка (15 минут)

**1. Сервер.** Минимальная машина у хостера в нужной стране: 1 ядро, 512 МБ, публичный
IPv4, Ubuntu 22.04 или новее. Стоит порядка чашки кофе в месяц. Вход по SSH-ключу,
пароль не заводить.

**2. Секрет и файлы.**
```bash
python3 -c "import secrets;print(secrets.token_urlsafe(24))"   # сохраните себе
scp gateway.py root@<сервер>:/opt/gw/gateway.py
```

**3. Сертификаты** (только если архивы вашей страны используют национальный
удостоверяющий центр). Соберите бандл и положите в `/opt/gw/ca-bundle.pem` —
как именно, описано в `../RECIPES.md`, раздел «Неполная цепочка сертификатов»:
корня мало, актуального промежуточного часто нет по общеизвестному адресу,
его адрес лежит в расширении AIA самого сертификата сайта.

**4. Служба.** `/etc/systemd/system/arch-gw.service`:
```ini
[Unit]
Description=Archive read-only gateway
After=network-online.target

[Service]
Environment=GW_TOKEN=<ваш секрет>
Environment=GW_PORT=80
Environment=GW_CA=/opt/gw/ca-bundle.pem
ExecStart=/usr/bin/python3 /opt/gw/gateway.py
Restart=always
RestartSec=3
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/opt/gw
AmbientCapabilities=CAP_NET_BIND_SERVICE
CapabilityBoundingSet=CAP_NET_BIND_SERVICE
MemoryMax=200M

[Install]
WantedBy=multi-user.target
```
```bash
chmod 600 /etc/systemd/system/arch-gw.service
systemctl daemon-reload && systemctl enable --now arch-gw
```

**5. Проверка — обязательно все пять пунктов:**
```bash
B=http://<сервер>/g/<секрет>
curl -s -o /dev/null -w "%{http_code}\n" "$B?url=https%3A%2F%2F<архив>%2F"   # 200
curl -s -o /dev/null -w "%{http_code}\n" "http://<сервер>/g/wrong?url=..."   # 404
curl -s -o /dev/null -w "%{http_code}\n" "$B?url=https://example.com/"       # 403
curl -s -o /dev/null -w "%{http_code}\n" "http://<сервер>/"                  # 404
curl -s -o /dev/null -X POST -w "%{http_code}\n" "$B?url=https://<архив>/"   # 405
```
Если хоть один ответ другой — не пользуйтесь, разбирайтесь: это открытый прокси.

## ⚠️ Цель передавать хвостом пути, а не параметром

Проверено на живом загрузчике: **строка запроса до сервера не доходит** — приходит голый
`/g/<секрет>`, и шлюз отвечает 400. В журнале это видно сразу: один и тот же путь даёт
200 с вашей машины и 400 от загрузчика.

Поэтому рабочая форма адреса — **без `?` и `&` вовсе**, цель уходит хвостом пути
в base64url:

```
http://<сервер>/g/<секрет>/<адрес в base64url>
http://<сервер>/gwar/<секрет>/<строка параметров в base64url>
```
```bash
python3 -c "import sys,base64;print(base64.urlsafe_b64encode(sys.argv[1].encode()).decode().rstrip('='))" \
        "https://<архив>/search?q=Иванов"
```

Адрес **без параметров** понимается и открытым текстом: `/g/<секрет>/https://<архив>/`.
Форма `?url=` тоже осталась — она удобна из терминала, где запрос никто не режет.

## Что сказать чату

> Чтобы открыть страницу, недоступную тебе напрямую, загружай адрес вида
> `http://<сервер>/g/<секрет>/<АДРЕС>`, где `<АДРЕС>` — полный адрес архивной страницы,
> закодированный в base64url (без знака `=` на конце). Адрес без параметров можно
> и как есть. Шлюз только читает и пропускает лишь архивные домены. 403 — домен не
> в списке, скажи мне. 404 — секрет неверный. Используй шлюз вместо ответа
> «источник недоступен».

## Переходник к источникам с POST-поиском

Часть порталов ищет не ссылкой, а запросом с телом (Elasticsearch и подобные) — чат так
не умеет. В коде есть пример узкого переходника: отдельный адрес `/gwar/<секрет>?last_name=…`
принимает GET с разрешёнными полями, **сам** собирает нужный POST и отдаёт JSON с местом
рождения, чином, частью, архивным шифром и ссылкой на карточку.

Как найти такой шлюз у другого портала — `../RECIPES.md`, «Поиск, спрятанный за POST».
Переходник пишется под каждый источник отдельно: **произвольное тело запроса наружу
пропускать нельзя.**

## Правила, которые нельзя ослаблять

Открытый в интернет пересыльщик сканеры находят за часы. В коде уже есть, менять не надо:

- секрет в адресе, всё остальное — 404 без подсказок;
- **белый список доменов** (`ALLOW` в начале файла) — правьте под свои архивы;
- только GET; POST/PUT/DELETE — 405;
- редирект за пределы белого списка обрывается;
- потолок 12 МБ на ответ и 60 запросов в минуту;
- порт в целевом адресе запрещён — иначе через шлюз видны внутренние сервисы;
- в журнал пишется путь без строки запроса: секрет и адреса туда не попадают.

⚠️ **Не давайте свой секрет посторонним.** Это доступ к вашему серверу, общий лимит
запросов и общий IP: чужая активность приведёт к бану вашего адреса у архива.
Каждому — свой шлюз, файл один и тот же.

⚠️ **Темп.** Шлюз не заменяет правил из `../RECIPES.md`, «Темп запросов»: у архивов
с платным доступом выгрузка быстрее человека — обход оплаты, и блокируют именно за это.

⚠️ Шлюз не логинится и не хранит сессий: читальные залы с входом по паролю так не открыть.

⚠️ HTTPS у него нет (на голый IP сертификат не выпустить). Если загрузчик откажется
брать `http://` — возьмите домен и выпустите сертификат.
