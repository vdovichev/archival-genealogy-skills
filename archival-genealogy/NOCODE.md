# Работа без исполнения кода — одним GET

Ассистент в браузере обычно **не имеет оболочки, но имеет инструменты веб-поиска и загрузки
страницы**. Их ограничение одно, зато жёсткое: это **GET без своих заголовков и без тела
запроса**. Отсюда правило:

> Источник доступен без кода ⟺ у него есть **GET-близнец**.
> Ищите его прежде, чем объявлять источник недоступным из чата.

## Где искать GET-близнеца

| Признак | Что пробовать |
|---|---|
| Библиотека, репозиторий, портал оцифровки | **OAI-PMH** — `/oai`, `/oai/OAIHandler`, `/oai/request`, `/cgi-bin/oai`. Отдаёт XML на `?verb=` |
| SPA с POST-поиском | публичная страница результата (`/search?q=`), карточка объекта (`/preview?id=`), `sitemap.xml` |
| Каталог с пагинацией | `?page=N&format=json`, `?output=json`, `.json` в конце пути |
| Движок на Yii/Bitrix | поиск и так GET — брать URL прямо из адресной строки |
| Совсем закрыто | внешний поисковик с ограничением по домену: `site:<домен> <фамилия>` |

⚠️ OAI-PMH — самый недооценённый вход. Он есть у большинства порталов оцифровки, отдаёт
метаданные всей коллекции постранично и **не требует ни ключа, ни POST**.

## Проверено (середина 2026 г.)

| Источник | GET-доступ | Команда/адрес |
|---|---|---|
| Движок «Архивный фонд» | ✅ | `/archive/search?search=<q>&morph=Y` |
| Движок «КАИСА» (простой поиск) | ✅ | `/search?type=simple&p.0.v=<q>&p.0.c=1582&p.0.a=15868` |
| Веб-архив CDX | ✅ JSON | `web.archive.org/cdx/search/cdx?url=<домен>&matchType=domain&output=json` |
| Литовский портал: **поиск** | ❌ 405 | `/vepis-api/internal/find` — только POST |
| Литовский портал: **карточка** | ✅ JSON | `/vepis-api/internal/findById?id=<ID>` |
| Литовский портал: **OAI-PMH** 🔑 | ✅ XML | `/oai/OAIHandler?verb=Identify` · `verb=ListSets` · `verb=ListIdentifiers&metadataPrefix=oai_edm&set=<set>&from=YYYY-MM-DD` · `verb=GetRecord&identifier=oai:<домен>:<ID>&metadataPrefix=oai_edm` |
| Историческая библиотека (elib) | ✅ | `/ru/nodes/search?query=<q>` |
| Народная база памяти (moypolk) | ✅ | `/search/soldiers?s=<ФИО>` |
| Нацбиблиотека (rusneb) | ⚠️ | отдаёт 403 «голому» клиенту; из браузера открывается |
| Списки репрессированных (openlist) | ⚠️ | 403 с части адресов — ограничение по стране, не отсутствие данных |

🔑 **Наборы OAI литовского портала**: `Archival_documents`, `Published_documents_and_manuscripts`,
`Card_catalog`, `Art`, `E_cinema`, `Video_audio_3D`. Формат метаданных один — `oai_edm`
(`oai_dc` не поддержан). Идентификатор в GetRecord пишется с префиксом `oai:<домен>:<ID>`.

## Чего одним GET не сделать

Полнотекстовый поиск по слою OCR (`includeFullText`), расширенный поиск с фасетами, базы
с сессией и CSRF (сводные военные базы), выгрузка образов пачкой. Для этого нужна среда,
где выполняется код, — `scripts/archnet.py`.

## Порядок в чате без кода

1. Внешний поисковик по домену — понять, есть ли фамилия/топоним у источника вообще.
2. GET-близнец (таблица выше) — получить структурированный ответ.
3. Карточка документа по `id` — шифр, годы, ссылка на образы.
4. Что не даётся — сформулировать **готовой командой** для среды с оболочкой,
   а не выдавать «источник недоступен».

⚠️ 403 и таймаут ≠ «данных нет». Это чаще ограничение по стране IP или защита от ботов;
тот же адрес из другого места открывается (`PITFALLS.md`, «Ложная недоступность»).


## Когда у ассистента только GET, а поиск требует POST

Ассистент в браузере не умеет отправлять тело запроса — значит источники с POST-поиском
(предыдущий раздел) для него закрыты, даже если сам сайт доступен. Обход один: **узкий
переходник** на машине, у которой доступ есть. Он принимает GET с понятными параметрами,
сам собирает нужный POST и возвращает ответ.

```
ассистент → GET  http://<ваш узел>/<секрет>?last_name=…&birth_place_uezd=…
переходник → POST https://<портал>/<шлюз>?builder=<Тип>  (тело собирает сам)
```

⚠️ Такой переходник — сервис, открытый в интернет. Без ограничений его находят сканеры
и начинают гонять через него чужой трафик. Минимум, ниже которого нельзя:

- **секрет в адресе**, всё остальное — 404 без подсказок;
- **белый список доменов**; произвольный адрес не пропускается;
- **произвольное тело запроса наружу не уходит** — переходник собирает его сам
  из перечня разрешённых полей;
- потолок на размер ответа и на число запросов в минуту;
- редирект за пределы белого списка обрывается;
- порт в целевом адресе запрещён — иначе через переходник видны внутренние сервисы;
- в журнал не пишется ни тело ответа, ни строка запроса с секретом.

Переходник не логинится и не хранит сессий: закрытые входом читальные залы так не открыть.

🔑 Готовый код такого шлюза и инструкция по установке — `gateway/`.

⚠️ **Ассистент может не уметь собирать адреса сам** — только загружать те, что дословно
встретились в переписке или в предыдущем ответе. Тогда одной рабочей ссылки мало:
переходник должен **переписывать ссылки внутри отдаваемых страниц** в свою форму,
иначе навигация обрывается на первой же странице. Проверяется просто: попросите
ассистента перейти по ссылке из полученной страницы.

⚠️ **Строку запроса загрузчик может срезать целиком.** Проверено: до сервера приходит
путь без `?...`, и переходник отвечает «параметр не получен». Поэтому адрес для
ассистента строится **без `?` и `&`** — цель уходит хвостом пути, закодированная
в base64url. Диагностируется мгновенно: в журнале сервера один и тот же путь даёт
200 с вашей машины и 400 от загрузчика.
